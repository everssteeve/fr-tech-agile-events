*Synthèse établie à partir des transcripts des talks (ce qui a été dit sur scène) : aucun retour de participant n'a été trouvé à ce jour.*

### 1. L'IA partout, mais surtout comme question de jugement
Près d'un talk sur deux parle d'IA, rarement pour la célébrer sans réserve. Le fil commun : quand le code devient abondant, **la valeur se déplace vers le jugement**. Una Kravets ouvre sur « savoir quoi construire » plutôt que la syntaxe ; Gabriel Pichot rappelle que le goulot « n'a jamais été la frappe mais la compréhension » ; Bree Hall défend le « goût » du développeur, que l'IA n'a pas. Kawtar Choubari dresse le catalogue des anti-patterns React que l'IA reproduit (`useEffect` superflus, accessibilité oubliée), et Dominik Dorfmeister note que l'IA génère beaucoup de code mort.

### 2. Les garde-fous déterministes comme contrepoids
La réponse partagée à l'IA n'est pas un meilleur prompt mais **un outillage qui ne ment pas** : TypeScript strict et lint à zéro erreur (Kitze, Choubari), types inférés de bout en bout (Tanner Linsley), Zod, plafonds de tours et validation humaine des actions destructives (Ankita Kulkarni, après un script qui aurait effacé ses données), Knip en CI (Dorfmeister), domain-lint pour les frontières entre features (Pichot).

### 3. Le front devient une interface pour agents
Plusieurs talks traitent l'agent comme un **second utilisateur** du front. Susanna Wong présente WebMCP, où l'app React expose ses fonctions comme outils ; Tanner Linsley conçoit le CLI de TanStack comme un serveur MCP ; Ankita Kulkarni pilote son activité via un bot Telegram outillé. Nikhil Sharma prend le contre-pied en appliquant du machine learning classique à la réconciliation React elle-même.

### 4. Performance : mesurer, puis verrouiller
Bloc fort de la fin du jour 1 : Mark Erikson montre une démarche quasi scientifique (benchmark, profiling, une hypothèse à la fois) pour gagner ~40 % sur Immer ; Nicolas Dubien transforme chaque régression corrigée chez Pigment en test end-to-end (fuites mémoire, compteur de rendus, long tasks). Côté données, Dan Neciu raconte comment des invalidations en cascade ont saturé une base, et Rody Gosset combine prefetch serveur et cache client pour supprimer les spinners. Le talk de Nadia Makarevich interroge le gain réel des Server Components (non vérifié sur transcript).

### 5. Écosystème : TanStack et Vite au centre, la stabilité revendiquée
TanStack traverse l'édition : Query (Neciu, Gosset, Dorfmeister), Router (migration PayFit), Start avec la **première présentation publique de ses server components** (Linsley, relayé par This Week in React). Côté outillage, Elise Patrikainen présente la chaîne Rust de VoidZero (Oxc, Rolldown, Vite 8, Vite+). Rom Brillout (Vike) et Daishi Kato (Zustand, Jotai, Valtio) défendent des **primitives stables et des cœurs minimaux** face aux frameworks qui imposent leurs choix. La plateforme web n'est pas en reste : CSS natif (Kravets), réfraction Liquid Glass en SVG (Chris Feijoo), accessibilité de l'authentification (Ramona Schwering).

### 6. Architecture et organisation : simplifier avant de fédérer
Deux retours d'expérience se répondent. Chez PayFit, Nicolas Beaussart-Hatchuel a **tué les micro-frontends** (32 dépôts, 6 bundlers) au profit d'un monorepo Nx, en misant sur la confiance (« never mandate, prove »). Chez Tesla, Taylor Quinn-Bohmann recourt à Module Federation pour partager un composant entre équipes, tout en reconnaissant qu'un monorepo suffit pour une seule équipe. Le choix dépend de l'organisation plus que de la technique.

### 7. Tensions et critiques
- **Maturité de l'IA** : Kitze juge que les modèles ne plafonnent pas et Susanna Wong que l'humain n'est plus le goulot ; au panel, Nicolas (PayFit) la voit s'effondrer au-delà de 3 dépôts et Faris Aziz la juge loin d'être prête pour la finance.
- **Juniors** : Kitze déconseille l'IA aux stagiaires et juniors ; Taylor Quinn-Bohmann défend leur embauche pour former des « systems thinkers ».
- **Inégalités de budget** : l'écart entre entreprises tient aux licences et rate limits (panel).
- **Soutenabilité de l'open source** : licence payante pour les grandes entreprises chez Vike, maintenances reprises par Daishi Kato et Mark Erikson.
- **Biais du corpus** : synthèse fondée uniquement sur les propos des speakers ; la réception par le public reste inconnue.
